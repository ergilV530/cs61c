	The cache-blocked version becomes faster

	the working set no longer fits in the cache 
	(typically around n = 1000 or larger, depending on the machine).
    Checkoff Question 2:
	Cache blocking only provides benefits when the matrix is large enough 
	that cache misses become a significant performance bottleneck. 
	For small matrices, most or all data already fits in the cache, 
	so blocking adds overhead (extra loop control) without improving locality. 
	When the matrix is large, blocking improves spatial and temporal locality, 
	reducing cache misses and improving performance.

    Checkoff Question 3:
	As blocksize increases, performance first improves and then degrades. 
	Initially, increasing blocksize improves locality because more data 
	within a block is reused before eviction. However, when blocksize 
	becomes too large, the block itself no longer fits well in cache, 
	leading to increased cache misses and worse performance.
